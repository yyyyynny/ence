# 검사

## 왜 저장소 안에 있나

전에는 검사가 임시 폴더에 살았다. 스위트 21종에 항목 944개까지 쌓였는데,
컨테이너가 한 번 재활용되면서 **통째로 사라졌다.** 앱은 멀쩡했지만 안전망이 0이 됐고,
그 사실을 다음 작업을 시작하고 나서야 알았다.

그래서 이번엔 검사를 **앱과 같이 커밋되는 파일**로 만들었다.
`js/selfcheck.js` 는 도구가 아니라 앱의 일부다. 앱이 열리는 곳이면 어디서든 돌아간다.

## 두 층

### 1. `js/selfcheck.js` — 판정이 사는 곳

의존성 없음. 앱과 함께 배포된다. 판정 논리는 **전부 여기 있다.**

```
주소 끝에 ?selfcheck 를 붙인다        → 저절로 돌고 결과가 화면에 뜬다
콘솔에서  SelfCheck.run()             → 결과 객체
콘솔에서  SelfCheck.check('contrast') → 한 가지만
SelfCheck.suites                      → 검사 이름 목록
```

`?selfcheck` 가 중요하다. **개발자도구를 못 여는 폰에서 열어 볼 수 있어야 실제로 돌리게 된다.**
이 앱을 쓰는 화면이 곧 검사하는 화면이다.

보는 것:

| | |
|---|---|
| 대비 | 반투명 조상을 차례로 합성해 **실제로 뒤에 깔린 색**을 구한 뒤 WCAG 비율. 이 앱은 표면이 전부 반투명이라 가장 가까운 배경만 보면 틀린다 |
| 터치 크기 | 44px. 상자가 작아도 `::after`나 음수 여백으로 넓힌 경우가 있어, **그 지점을 실제로 눌러 무엇이 잡히는지**로 판정 |
| 가로 넘침 | 문서와 요소 단위. 의도된 스크롤러는 예외 |
| 테마 짝 | `:root.theme-<id>` 와 `.theme-pv.theme-<id>` 가 짝으로 있는지를 **규칙을 읽지 않고 기능으로** 확인 (탐침 요소를 붙여 놓고 뿌리 테마를 바꿔 본다) |
| 토큰 불변식 | surface-1/2 가 같은 색의 두 알파인지, 맞음이 초록·틀림이 빨강 색상각인지 — 주석으로만 적혀 있던 약속을 실행 |
| 글꼴 굵기 | 쓰는 굵기를 실제로 받아 왔는지 (안 받아 오면 브라우저가 가짜로 굵게 만든다) |
| 그림문자 | 화면에 이모지 0. **화학 표기 `→ ↓ ↑`, 위·아래 첨자는 허용** — 학습 내용이지 장식이 아니다 |
| 모션 | 움직임 줄이기에서 상호작용 시간은 0, **그림 시간은 줄이지 않음** (전자가 중간에 멈추면 전자 배치가 틀리게 보인다) |
| 모드 | 전 구역 × 전 모드가 오류 없이 뜨고, 화면이 비지 않고, `undefined`/`NaN` 이 안 보이는지 |
| 창 | 네 창이 실제로 보이게 열리고 닫히는지 |
| 판 번호 | `APP_VERSION` · `CHANGELOG` 맨 앞 · `?v=` 전부가 같은지 |
| 그림 안 글자 | SVG `<text>`가 **화면에 그려지는** 크기. viewBox 배율만큼 같이 줄어드는데 `getComputedStyle`은 줄기 전 값을 돌려주므로, 글자 크기 검사는 이걸 못 본다 — 실제로 12px로 선언한 캡션이 폰에서 6.1px로 그려지고 있었다 |
| 참고 자료 | 힌트 창(`#reactionList`)의 항목 수가 구역별 반응식+이온식 개수와 맞는지. 한동안 이 창이 반응식만 알고 있어서 「고2 화학」에서 이온식 쓰기를 풀다 힌트를 눌러도 이온식이 하나도 안 보였다 |

### 1-b. `test/chem.mjs` · `test/diagram.mjs` — 내용이 맞는지

브라우저가 필요 없다. `node test/chem.mjs`, `node test/diagram.mjs`.

이 앱은 공부하라고 만든 것이라 **화면이 예쁜 것보다 내용이 맞는 게 먼저다.**
위의 `selfcheck` 는 "보이는가"를 보고, 이 둘은 "맞는가"를 본다.

- **`chem.mjs`** — 원소 118종의 기호·족·주기·분류, 1~20번 껍질 배치와 원자가 전자,
  이온 형성과 그 이름(음이온은 「-화 이온」이다), 이온식 표기, 앙금의 화학식·색·전하 균형,
  화학 결합의 전자 수지와 옥텟, 반응식 16건과 계수 템플릿 7건의 원자 수지·기약 계수,
  오비탈, 불꽃 반응, 퀴즈 좌표의 유일성, 키패드에 필요한 기호가 다 있는지.

  **기준표를 `js/data.js` 에서 가져오지 않는다.** 가져오면 같은 값을 두 번 읽을 뿐이라
  아무것도 못 잡는다. 파일 안에 따로 적어 두고 대조한다.

- **`diagram.mjs`** — 그린 SVG의 좌표를 되읽어 잰다. 전자끼리 겹치는지, 원자핵을
  침범하는지, viewBox 밖으로 나가는지(화살표·대괄호·전하까지), 최종 화면의 전자 수가
  맞는지, 안내선·캡션·`alt` 의 숫자가 그림과 같은지, 같은 이온을 두 화면이 같게 그리는지.

  **`dia-e-gone`(빠져나가는 전자)은 최외각 판정에서 뺀다.** 넣고 세면 이온이 아니라
  원자를 세게 되고, 전에 그것 때문에 실제 버그를 통과시킨 적이 있다.

### 2. `test/run.mjs` — 조건을 바꿔 가며 위를 반복

```
npm i --no-save playwright     # 앱에는 의존성을 넣지 않는다. 여기만 쓴다
node test/run.mjs
node test/run.mjs --themes=note,edit    # 일부만
```

- **`file://` 로 연다. 서버를 안 띄운다.** 이 앱은 파일로 열어도 돌아가야 하고,
  그걸 "지켜야 한다"고 적어 두는 대신 매번 실제로 확인한다.
- 폭 5종(320·360·390·414·1024) × 테마 전부 × 움직임 줄이기 × **글꼴 차단 1회**
  (학교 망에서 Google Fonts 가 막히는 일이 실제로 있다 — 그때도 읽혀야 한다).
- 테마 목록을 앱의 등록처(`THEMES`)에서 읽는다. 테마를 늘리면 검사도 저절로 늘어난다.
- 브라우저 경로는 글롭으로 찾는다. 빌드 번호를 박아 두면 다음 컨테이너에서 깨진다.

## `.mcp.json` 의 Playwright 는 이게 아니다

그건 **손으로 들여다볼 때** 쓰는 것이다. 회귀 안전망은 이 폴더다.
MCP 에 기대는 순간 검사가 다시 저장소 밖으로 나가고, 그래서 지난번에 없어졌다.

## 검사가 실패하면

**코드가 틀린 건지 기준값이 낡은 건지 먼저 가른다.** 기준값을 고칠 때는 왜 고쳤는지를
`js/selfcheck.js` 에 적는다. 이유 없이 기준을 낮추면 검사는 그때부터 아무것도 안 잡는다.
